# A2A shared work-object reducer witness v0.1

This directory defines a pure, deterministic, offline reference reducer for one
caller-supplied work object and one caller-ordered list of operations. It gives
opaque cross-client actors a shared optimistic-revision algebra for fields,
append-only notes, and terminal finalization.

The reducer does not decide operation order. It assumes an external authority
already linearized the list and evaluates that exact order. Competing operations
with the same expected revision demonstrate deterministic first-applied wins and
stale rejection; they do not implement an unordered merge algorithm.

## Semantic boundary

- `set_field`, `remove_field`, `append_note`, and `finalize` are the only
  operations.
- Accepted operations increment revision exactly once.
- Rejected and idempotent operations never mutate state.
- Exact operation retries are idempotent within the supplied trace.
- Reusing an operation ID with different content rejects before all other
  checks.
- A final object rejects new operations before checking expected revision.
- `final` freezes only mutation of this modeled object. It is not task,
  attempt, agent, fleet, cancellation, settlement, or recovery lifecycle state.
- Object keys and strings use exact Unicode scalar semantics with no
  normalization, trimming, aliases, or locale folding.
- Named-client corpus labels are opaque examples, not behavioral claims.

If a test needs a transport, model ID, envelope, clock, lease grant, quorum,
policy engine, credential, filesystem artifact, database, or tool execution, it
belongs in another lane.

The checked-in corpus expectations are frozen review targets and are never
regenerated by an evaluator under test.

This witness is not a CRDT or OT system. It does not discover peers, choose an
authority, sort concurrent input, route work, transport content, authenticate
actors, authorize mutations, persist state, execute tools, or prove production
interoperability.
